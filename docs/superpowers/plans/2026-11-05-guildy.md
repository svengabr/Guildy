# Guildy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Blizzard-styled replacement for the guild window in WoW Forever with chat-first layout, census, professions/recipe search and Guildy-to-Guildy sync.

**Architecture:** One addon table `ns`. Pure modules in `Core/` (no WoW API at load or call time, unit-tested under LuaJIT), thin game adapters in `Game/` (roster, chat, trade-skill scan, chat links, sync network, window redirect), frames in `UI/`. `Core/Init.lua` wires events last.

**Tech Stack:** Lua 5.1 (WoW Forever, `## Interface: 16001`), LibDeflate + json.lua copied from Raidy, LuaJIT test harness copied from Raidy (`luajit tests/run.lua`), luacheck via docker.

**Spec:** `docs/superpowers/specs/2026-11-05-guildy-design.md` (incl. §9a decisions)

## Global Constraints

- `## Interface: 16001` only; SavedVariables `GuildyDB` (account-wide).
- English in code, comments, commits, docs; player-facing strings only via `ns.L` (English base + deDE).
- Every WoW API call that the Forever docs do not list is existence-checked (`rawget(_G, ...)`) and pcall'd where it can error.
- Pure logic in `Core/` takes plain tables and `now` as arguments, never calls WoW API.
- Addon prefix `GUILDY`; channel `GUILD` only; send budget 800 B/s, burst 2000 B (Raidy values).
- Activity windows: 30, 90, 180 days, or all; default 30.
- Level brackets: 1–9, 10–19, 20–29, 30–39, 40–49, 50–60.
- Chat tab is always selected when the window opens.

## Review Focus

1. **Roster not loaded yet** (first open right after login, `GetNumGuildMembers()==0`) → window shows "loading", no Lua error; census with zero members returns zeros, no division by zero. Test: `Census.Compute({}, ...)`.
2. **Unknown / missing last-online** (online members return nil from `GetGuildRosterLastOnline`) → online counts as active; offline with nil counts as inactive except in "all". Test in `test_census.lua`.
3. **Hostile / garbage sync payloads** (wrong types, huge recipe lists, record about the receiver's own character) → ignored, no error. Tests: `Professions.ValidateRecord`, `Professions.Merge` with own-character guard.
4. **Recipe search input** with Lua pattern characters (`[`, `%`, `-`) or an item link → plain-text match, no error. Test: `Search.Recipes(entries, "[Elixir")`.
5. **Names with realm/last-name suffix** ("Ranfredo-Blanko", "Ran Fred-Realm") match roster names. Test: `Names.Key`.

## Data model (Core/Store.lua, Core/Professions.lua)

```
GuildyDB = {
  version = 1,
  settings = { activityDays = 30, share = true, size = {w,h}, point = {...} },
  guilds = { [guildKey] = { members = { [nameKey] = MemberRec } } },
}
MemberRec = { name = "Ran Fred", profs = { [skillLineID] = ProfRec } }
ProfRec   = { rank = n|nil, max = n|nil, recipes = { spellID, ... } | nil, ts = epochSeconds, src = "self"|"relay"|"link"|"scan" }
```
`guildKey` = guild name .. "@" .. (GetNormalizedRealmName() or "?"). `nameKey` = `Names.Key(name)`.
`src="scan"` = own scan on this account, treated like `self` when sending.

### Task 2: Census (Core/Census.lua)

**Produces:**
- `Census.DaysOffline(years, months, days, hours) -> number|nil` (nil when all nil) = y*365+m*30+d+h/24.
- `Census.IsActive(m, windowDays) -> bool`; m = `{online, daysOffline}`; `windowDays == nil` → true; online → true; nil daysOffline → false.
- `Census.Bracket(level) -> 1..6` (`min(6, floor(level/10)+1)`, level 60 → 6).
- `Census.Compute(members, windowDays, profsOf) -> {total, active, online, avgLevel, classes={[CLASS]=n}, brackets={n1..n6}, professions={[skillLineID]=n}, withProfessions, newCount}`; `profsOf(member) -> {skillLineID=true}|nil`; `newCount` counts members with `joinedDaysAgo` ≤ 30 (nil ignored).

- [ ] Tests (`tests/test_census.lua`): Bracket(1)=1, Bracket(9)=1, Bracket(10)=2, Bracket(60)=6; IsActive online+nil→true, offline nil→false, 29.9 days in 30→true, 30.5→false, window nil→true; Compute({}) → total 0, active 0, avgLevel 0; Compute of 3 members (one inactive) counts only active in classes/brackets/professions, `total` = 3.

### Task 3: Professions model + search (Core/Professions.lua, Core/Search.lua)

**Produces:**
- `Professions.SKILL_LINES` = `{[171]="ALCHEMY",[164]="BLACKSMITHING",[333]="ENCHANTING",[202]="ENGINEERING",[182]="HERBALISM",[165]="LEATHERWORKING",[186]="MINING",[393]="SKINNING",[197]="TAILORING",[185]="COOKING",[129]="FIRST_AID",[356]="FISHING"}`; `Professions.PRIMARY` set (first nine).
- `Professions.ValidateRecord(r) -> ProfRec|nil`: numbers clamped 0..450, recipes only positive integers, max 1000 recipes, ts number required, src in allowed set.
- `Professions.Merge(member, skillLineID, incoming, ctx) -> changed:bool`; ctx `{ownKeys = {nameKey=true}, memberKey}`: rejects relayed records about own characters; newer ts wins; equal ts: `self`/`scan` beats `relay`/`link`; a newer record without recipes keeps the old recipe list when the old record had one.
- `Professions.Digest(guild) -> { [nameKey] = maxTs }`.
- `Search.Recipes(entries, query) -> list`; entries `{ {memberName, skillLineID, spellID, recipeName} }`; query trimmed, item-link brackets stripped (`|h[Name]|h` → `Name`), case-insensitive plain `find(q, 1, true)` on `Names.Lower`; results sorted: prefix match first, then recipe name, then member name; max 200.

- [ ] Tests (`test_professions.lua`, `test_search.lua`): validate rejects string ts and negative recipe ids, truncates 1500 recipes to 1000; merge newer wins; merge older ignored; relay about own key rejected; equal-ts self beats relay; recipe-less newer keeps recipes; Digest picks max ts; Search "[Elixir" matches "Elixir of Lion's Strength"; "%" does not error; link input works; prefix ordering.
- [ ] Implement, pass, commit `feat: profession records and recipe search`.

### Task 10: Sync

**Files:** `Game/Network.lua` (Raidy queue/throttle, channel GUILD), `Game/Sync.lua`.
